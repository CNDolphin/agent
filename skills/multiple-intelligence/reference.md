# 多元智能自动解读 Agent · 口径与约束参考

来源:《多元智能自动解读Agent-全功能逻辑与使用流程详解》v1.0(2026-11-16,对应代码基线 I-048,覆盖需求 I-001 ~ I-048)。
本文件给接手开发的工程师查阅,**不会**被 `skill_loader` 加载进对话提示词(加载器只读 `*/SKILL.md`)。

## 1. 产品定位
一次检测 -> 终身潜能档案 -> 越用越懂你的成长顾问。报告只是档案的第 1 条记录。
由此带来三个架构选择:需要持久化(档案)、需要上下文问答(陪伴引擎 + 对话层)、涉及未成年人隐私因此纯本地部署。

交付形态:单文件 HTML(localStorage)、桌面本地版(Python 标准库服务 + Edge `--app`,端口 8765)、线上分享链接。
三者共用同一构建产物,`storeInit()` 探测 `/api/health` 可达则走桌面 API,否则回退 localStorage。

设计红线(硬约束):无报告不出处方;不贴标签;事实与推断分开;回放 ≠ 重算。

## 2. 智能与指标编码
id 是英文单词而非首字母缩写(曾因误写 `l/v/m` 取不到分组)。

| 顺序 | id | 名称 | 能力项前缀 |
|---|---|---|---|
| 1 | lang | 语言 | l1-l5 |
| 2 | logic | 逻辑数学 | g1-g5 |
| 3 | visual | 视觉空间 | v1-v5 |
| 4 | nature | 自然观察 | n1-n5 |
| 5 | music | 音乐 | m1-m5 |
| 6 | body | 肢体动觉 | b1-b5 |
| 7 | social | 人际交往 | s1-s5 |
| 8 | inner | 内省 | i1-i5 |

8 智能 x 5 项 = 40 项,0-100 分,55 为标准分(50 为全国均值锚点)。

## 3. 三源融合(FUSION-1.0)
采集路径:A 问卷 40 题(I-048 起;早期版本为 80 题)、B 主观排序 48 项(序数)、C 基因检测 8 个智能分(仅智能级)。

```
场景A(有问卷+排序,无基因): inner = 0.4*问卷分 + 0.6*排序目标分
场景B(有基因):               最终  = 0.65*基因分 + 0.35*场景A结果
```

第一层能力级混合之后,还有第二层「智能级整组位移」:整组向排序目标均值靠拢(权重 0.5),防止能力级与智能级双重过度调整。
排序目标分:能力级 1-5 名 -> 75/65/55/45/35;智能级 1-8 名 -> 72.5 -> 37.5。
反转豁免:问卷分 >77 或 <33 的能力项跳过混合与位移,保留原始值。

必须同时遵守:
1. 排序缺失不参与:该指标直接取问卷分。
2. 权重是专家先验,非临床校准;报告与文档必须保留免责说明,不得称「实证最优」。
3. 口径一旦变更必须升级 `fusionVer`(当前 `FUSION-1.0`,常量 `ARCHIVE_FUSION_VER`),否则历史档案无法区分「旧口径」与「数据不同」。

基因数据存储:
- 分值存独立对象 `g_geneScores`(按项记录、含覆盖计数),与输入框展示值解耦——重做问卷只更新问卷源与展示,不清空已导入基因数据;仅「清空」「示例数据」或档案回放时显式重置。
- 写入点共四个:录入区手动输入、粘贴 JSON、PDF 导入、对话内应用分数。
- 报告差异对比块的基因列只对已覆盖指标求均值,覆盖数 `geneN` 一并返回。

PDF 指标换算:`指标分 = 智能分 x (该指标比率 / 该智能 5 项比率均值)`,智能分缺失按 55 锚定并警告。
PDF 非模板或扫描件:明确提示未能识别,不猜测、不填部分值。

分享链接:通过 `?s=` 进入时 40 项分数直接注入,置 `g_linkLoaded=true`,不再二次融合,保证回放 ≠ 重算。

## 4. 对话意图判定(I-048 十类优先级,顺序不可交换)
1. crisis/危机内容:最高优先,直接转入危机流程。
2. report:必须指向「报告/结果/解读这份」,裸「分析一下」不算。
3. event:「最近/今天/昨天」+ 行为描述;含「为什么/什么原因/怎么办/分析/下滑」等提问语气则豁免。
4. subject(学科潜能):命中学科名;提问语气转 advise。
5. advise:提问语气 + 命中 `COACH_DOMAIN` 关键词 -> 带证据建议。
6. scores:数字须紧跟智能/指标名,且带「分」或 >=20,避免「8 岁」被判成 8 分。
7. profile/build:抽取年龄、性别、称呼、目的;「我儿子/女儿」可推断性别。
8. onboarding:仅当 `touchedProfile` 为真且 `!advise && !event && !subject`。
9. knowledge:知识库命中 -> 科普。
10. chitchat:兜底。

三条铁律:
- 裁决卡只属 decision:advise 分支不得无条件生成裁决卡;只有「归因 + 该不该」的混合问法才追加裁决卡,且排在处方之后。
- 裸「还是」不算选择语境:`chatLooksLikeCompare` 需出现「学什么/报什么/哪个好」或明确比较对象。
- 改分支先看顺序:任何意图分支改动,先核对 `chatIntent` 与 `chatTurn` 分支顺序的一致性。

分层:`chatTurn(text, st)` 纯逻辑不碰 DOM,返回 `{state, msgs, chips, act}`;副作用只由 `chatRunAct` 落地,保证可重放可单测。

## 5. 表达规范与 LLM 风格守卫链
五条口径:`LLM_STYLE_RULES` 是唯一真源,经 `llmStylePromptBlock()` 注入 system prompt(含正反例)。
1. 结论先行,先回答再展开;一次只问一个问题。
2. 不贴标签:禁止「懒」「多动症」「垫底」等定性;低分说「靠后 / 最值得补的地方」。
3. 术语翻译成用户能懂的话,不直接抛枚举值。
4. 事实与推断分开标注,证据不足直说。
5. 不用 Markdown 堆砌,长度受限。

模型输出后经 `llmStyleGuard()` 硬清洗,顺序固定:术语替换表 -> 标签软化 -> 人格定性改写(「他就是懒」->「这次更像是还没找到动力」;「多动症」->「需专业评估」)-> 枚举翻译(mix ->「两者都有」)-> 去 Markdown -> 超长按句裁剪 -> 多问句收敛为 1 个。

两类问题只标记不改写(避免语序风险):开头无结论信号(`no-conclusion`)、断言与推断混杂无标注(`mixed-inference`)。
守卫链位置:在 `mirEnforce`(严重违规三闸门)之后执行。
注意:规则自生成的回复不过守卫链(会被误裁三段),手写文案必须同步遵守五条规范。

## 6. 档案与陪伴
- 回放(`archiveReplay`):按快照原样复现,不改历史。重算(`archiveRecompute`):用留档 `source.raw` 按当前口径生成新视图,同样不改历史。二者不可混用。
- 自动存档:串行队列避免并发写坏存储;去重键 = 当天 + 相同 40 项原始录入 + 相同 profile。
- 存档内容(`archiveFromReport`):`fusionVer`、`source.raw`、`quizAnswers`,保证可回放可重算。
- 归因三分法 `coachAttribute`:能力基础 x 近 14 天事件密度(>=2 为密)x 强度 -> `trait` / `env` / `mix` / `none`。
- 归因分水平:能力分 >=60 禁说「最薄的一环」,走 env 口径;45-60 才给推断。
- 证据链硬约束:每条动作至少挂 1 条能力项证据;有关联事件再挂事件证据;无报告不出处方,只输出「补齐依据」。`evidence.kind` 仅 `ind` / `intel` / `event`。
- 把握度:事件记录少于 2 条时封顶「中等」,并说明原因。
- 处方剧本 `COACH_PLAYBOOK`:9 域 x 4 条(lev/tgt/env/trait),按归因择 3 条,每轮最多推进 2 条;`lev` 块不得引用 `c.tgt`,`tgt` 块不得引用 `c.lev`。
- 上下文连贯:对话状态 `st.last` 记录上一轮上下文;同域追问先引用上次给的两条,再从第 3 条继续;给完转反馈循环。
- 学科潜能:`0.5*能力项均分 + 0.3*兴趣事件密度 + 0.2*当前表现`;无事件标「待验证」;`n>=2` 且 >=65 才判强潜能。
- 泛化前置检测:出现「做什么事都/干什么都/事事都」+ 磨蹭/拖延 -> 按习惯(`habit`)域处理。
- 兴趣画像:七类词表每轮静默抽取 `traits`(存教练层,同 kind+text 去重,80 条上限,随成员隔离);advise/focus 开场可引用最近兴趣。
- 加密包:PBKDF2-SHA256(15 万次)+ AES-GCM 256,口令 >=6 位;仅覆盖导出包,本地落盘仍是明文(已知限制 R-02)。
- 本地 LLM 润色只做可选增强,只润色不改结论、不新增事实,任一步失败回退模板原文。

## 7. 辅助能力与运行时
- TTS:`ttsChunks` 清洗文本(Markdown 符号、标点转停顿)并按句切分为 <=120 字的块,上限 8 块;一轮回复只聚合朗读一次(`chatSpeakText`),`kind:'card'` 跳过。
- 语音输入:音频/视频 -> 抽音轨 -> 16k 单声道 -> 本地 Whisper-base 转写(CDN 懒加载,首次约 50MB) -> 清洗后填入输入框,用户核对后手动发送;上限 120MB / 10 分钟。
- PDF 导入:内联 pdf.js(fake worker,file:// 可用);导入后双路写入——40 项指标分进输入框并计入 `g_geneScores`,8 智能分写 `intelManual`;报告内智能排序不写 `g_ranks`(先天报告与主观排序语义不同)。
- 成员隔离:键作用域 `mi_archive_v1__<mid>` / `mi_coach_v1__<mid>`;新建/改名/删除必须用自制 modal,禁用原生 `prompt`/`confirm`。
- 分享链接:`?s=` 携带 40 项分数必须手拼逗号分隔(`URLSearchParams` 会把逗号转义为 `%2C`);通过链接打开只展示不落库。
- 桌面运行时:`desktop/server.py` 数据落盘 `data/members/<成员id>/{archives, coach.json}`;`/api/llm/*` 只转发本机回环 Ollama;服务仅绑 `127.0.0.1`。
- 热更新:页面 URL 带 `?v=<修改时间-大小>` 指纹;服务端单实例复用;页面内 `appVersionWatch()` 每 30 秒 + 聚焦时比对版本。
- 构建:模块拼接顺序不可调(vendor -> 数据 -> 引擎 -> 存储 -> 陪伴 -> UI -> PDF -> 知识库 -> 对话,`agent_chat.js` 末位);`agent_rules.js` 是打包产物,勿手改。

## 8. 质量保障
- 自动化测试 18 套 / 1116 断言,改动前后必须全绿;不要直接改构建产物。
- 无头探针:必须以 `window.addEventListener('load', …)` 包裹,结果写入 `#probe-out`,用 Python 正则提取(避免中文截断);不用 `--virtual-time-budget`,布局用 `getBoundingClientRect` 判断。
- 排查口诀:先证逻辑(真实档案跑对话)-> 再证产物(服务端首页与磁盘文件比对)-> 最后比对进程启动/窗口加载/产物构建时间。

## 9. 已知限制(摘要)
线上版落后多个版本(R-01);数据明文落盘(R-02);排序数据全成员共享(R-04);无鉴权(R-05);8 题自评为近似值(R-07);权重未经临床校准(R-08);新用户归因多为 `none`(R-09);PDF 模板改版需重校映射(R-10)。

## 10. 与本项目 mhagent 的关系
- 本 skill 位于运行时 `skills/`,只有 `SKILL.md` 正文会经 `build_system_prompt` 进入提示词;`DEFAULT_MAX_CHARS = 2600`,`BASE_PROMPT` 占 331,正文可用约 2259 字,超长会被截断(截断即口径丢失)。
- `reference.md` 仅供开发者查阅,不占提示词预算,可写全量细节。
- 基因报告读取/解读仍由 `gene-guidance`(暂未启用)把关;`route()` 对含「基因」的话优先路由到它。
- 路由前置规则见 `mhagent/skill_loader.py` 的 `_MULTIPLE_INTELLIGENCE_MARKERS`。
- 发布态读密文包 `mhagent/data/skills.enc`;任何技能正文改动后必须执行
  `python scripts/encrypt_skills.py --verify` 重建,否则发布包仍是旧口径。
