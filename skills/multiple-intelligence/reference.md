# 多元智能自动解读 Agent · 口径与约束参考

来源:《多元智能自动解读Agent-全功能逻辑与使用流程详解》v1.0(对应 I-048)与《多元智能自动解读Agent-源代码说明书》v1.0(对应代码基线 I-051,2026-11-16),并逐条核对 16 个运行模块源码。
本文件给接手开发的工程师查阅,**不会**被 `skill_loader` 加载进对话提示词(加载器只读 `*/SKILL.md`),因此可以写全量细节。

## 1. 产品定位
一次检测 → 终身潜能档案 → 越用越懂你的成长顾问。报告只是档案的第 1 条记录。
由此带来三个架构选择:需要持久化(档案)、需要上下文问答(陪伴引擎 + 对话层)、涉及未成年人隐私因此纯本地部署。

交付形态:单文件 HTML(localStorage)、桌面本地版(Python 标准库服务 + Edge `--app`,端口 8765)、线上分享链接。
三者共用同一构建产物,`storeInit()` 探测 `/api/health` 可达则走桌面 API,否则回退 localStorage。

设计红线(硬约束):无报告不出处方;不贴标签;事实与推断分开;回放 ≠ 重算。

## 2. 智能与指标编码
id 是英文单词而非首字母缩写(曾因误写 `l/v/m` 取不到分组)。

| 顺序 | id | 名称 | 能力项 | 左/右脑 | 角色 |
|---|---|---|---|---|---|
| 1 | lang | 语言 | l1-l5 | 左 | 学习能力预备 |
| 2 | logic | 逻辑数学 | g1-g5 | 左 | 学习能力 |
| 3 | visual | 视觉空间 | v1-v5 | 右 | 兴趣品味 |
| 4 | nature | 自然观察 | n1-n5 | 左 | 兴趣品味 |
| 5 | music | 音乐 | m1-m5 | 右 | 兴趣品味 |
| 6 | body | 肢体动觉 | b1-b5 | 右 | 兴趣品味 |
| 7 | social | 人际沟通 | s1-s5 | 右 | 情商综合 |
| 8 | inner | 个人内省 | i1-i5 | 左 | 情商综合 |

8 智能 × 5 项 = 40 项,0-100 分,55 为标准分(50 为全国均值锚点)。
数据契约:任何「分数对象」都是 `{指标键: 数值}` 扁平结构(键即 IND 的键),问卷分、基因分、融合终值、档案存档共用同一结构,可互相覆盖与比较。
扩展指标必须同步四处:`INTEL[].inds`、`QUZ` 题库、`BLOCK_ANALYSIS` 等文案库、`?s=` 链接的 40 项顺序。

## 3. 三源融合(FUSION-1.0)
采集路径:A 问卷 40 题(≥10 项才算有效)、B 主观排序 48 项(序数)、C 基因检测 8 个智能分。

### 3.1 场景判定
```
无问卷、无排序、无基因        → 不融合(返回 null)
有基因(且对象非空)          → 场景 B(基因 × 问卷/排序);只有基因、无问卷无排序 → 不融合
无基因 + 有问卷              → 场景 A(问卷 × 排序)
无基因 + 无问卷 + 有排序      → 场景 R(仅排序)
```
- `hasGene` 必须要求基因对象**非空**(I-051 修复:空对象曾被误判为有基因,整批分数被 0.65 权重拉低)。
- 权重:场景 A = 0.4×问卷 + 0.6×排序目标分;场景 B = 0.65×基因 + 0.35×场景A结果;场景 R = 100% 排序。
- 场景 R 未排名的项直接取 50(中性值),不是保留 0。
- 融合只对基因实际覆盖的指标叠加(`Number.isFinite(gene[k])`);未覆盖项退回场景 A 值,不拿问卷值冒充基因。

### 3.2 排序目标分与整组位移
```
能力级 1-5 名 → 75 / 65 / 55 / 45 / 35
智能级 1-8 名 → 72.5 / 67.5 / 62.5 / 57.5 / 52.5 / 47.5 / 42.5 / 37.5
```
第一层能力级混合之后,第二层「智能级整组位移」:该智能下所有指标均值向排序目标靠拢,位移量 = (目标 − 当前均值) × 0.5(防双重过度调整)。位移基准均值只由非反转项计算;整组都是反转项则全组豁免。

### 3.3 反转豁免
`isReversalScore(v) = v > 77 || v < 33`。极端项跳过能力级混合与智能级位移,保留原始值。返回值带 `exemptN`(豁免计数)供报告标注。

### 3.4 基因数据存储
- 分值存独立对象 `g_geneScores`(按项记录、含覆盖数 `geneN`),与输入框展示值解耦。
- 四个写入点:录入区手动输入、粘贴 JSON、PDF 导入、对话内应用分数。四点都必须同时写 `g_geneEdited[k] = true` 与 `g_geneScores[k] = 值`。
- 清空只在 `clearInputs()`、`fillExample()`、档案回放三处;`quizApply()` 不清空(I-051 修复:重做问卷不该丢基因报告)。
- 报告差异对比块的基因列只对已覆盖指标求均值,部分导入不虚高。

### 3.5 报告对象 R 结构
`analyzeReport(scores, meta, intelManual)` 是「分数 → 结论对象」的唯一入口:

| 字段 | 口径 |
|---|---|
| `intelScores` | 8 项智能分;`intelManual` 有值时直接采用报告值(优先级高于 5 项均值) |
| `rank` / `ratio` | 8 项按分数降序排名;`ratio` = 该项分数 ÷ 8 项总分 × 100 |
| `adv` / `boost` / `weak` | 三分法:1-3 名为优势、4-6 名为提升、7-8 名为补足 |
| `revHigh` / `revLow` | 分数 >77 / <33 的项,指标级与智能级都检;高分降序、低分升序 |
| `diagonals` | 四条学习线,分数 = 两条智能均值,降序 |
| `lScore` / `rScore` | 左脑(lang/logic/nature/inner)与右脑(visual/music/body/social)均值 |
| `wudao` | 学习五道,分数 = 各道指标集合均值,降序 |
| `s1` | 六项先天学习能力 l1、l4、g1、g2、g3、g4 的均值 |
| `s2` | 40 项总均值 |
| `talents` / `majors` / `careers` | 才艺 / 专业 / 职业库,`fit` = 匹配智能的 `intelScores` 均值,降序 |
| `courses` | 课程库,`fit` = 对应指标 `scores` 均值,降序 |
| `behaviors` | 行为库,`fit` = 关联指标 `scores` 均值,升序(越低越可能是当前要面对的问题) |
| `script` | 以强带弱话术:优势智能 → 其中最高细项,带动最弱智能 → 其中最低细项,附 `IND[botInd].adv` |
| `topics` | 专题模块列表(见 5.4) |

## 4. 解读素材库(agent_data2.js / agent_topic.js)

### 4.1 块状分析(同一智能内部的结构关系)
- 语言:阅读/口语/书写 = 读说写三通道;理解/感受 = 理性(论说) vs 感性(叙事)。
- 逻辑:归纳 vs 演绎(聚敛 vs 开放);运算+实验(操作/执行)vs 思辩+归纳+演绎(思考);思辩+实验 = 思考落到生活的程度。
- 视觉:图像 vs 空间(平面 vs 立体);绘图 vs 组砌(平面创作 vs 立体创作);组砌+绘图 vs 图像+色彩+空间(执行面 vs 感知面)。
- 自然:关怀+观察 vs 识别+分类(感性 vs 理性);观察→探索→识别→分类(认知递进链)。
- 音乐:表现 vs 创作(复制 vs 原创);感受 vs 鉴赏(感性 vs 理性);敏感是其余核心指标的基础。
- 肢体:反应/平衡/律动(大肌肉)vs 触感/操控(小肌肉)。
- 人际:领导 vs 协同(主导 vs 配合);沟通+协同 vs 沟通+领导(合作式 vs 领导式);了解 vs 感同(认知 vs 情意)。
- 内省:对他人 洞察→同理→慈爱;对自己 洞察→反省→自律。

| 实验 / 组砌 / 操控 | 动手 | 试验组织执行 / 平面到立体实现 / 大小肌肉精细操作 |
| 关怀 vs 慈爱 | 爱的表达 | 具体动植物怜悯 / 博爱并付诸行动 |
| 感同 vs 同理 | 理解他人 | 同情怜悯感受 / 尊重平等理解 |
| 口语 vs 沟通 | 表达 | 单向自我表达 / 双向互动 |

### 4.5 才艺 / 专业 / 职业 / 课程
- 才艺 25 项、专业 30 类、职业 30 类、课程 32 门;均按 `fit` 降序取前几项,并附建议年龄。
- 匹配口径:才艺/专业/职业 = 匹配智能均值;课程 = 对应能力项均值。
- 建议年龄依据《智能开发最佳时期对应表》《天赋智能时效窗》与敏感期,如:绘画 3 岁+(窗 0-12)、围棋/珠心算 4 岁+(逻辑窗 4-12)、声乐/钢琴 4-6 岁、书法 6 岁+、写作 7 岁+、大球类 6 岁+(团体运动窗 6-10)。
- 2026 增补:少儿编程(6 岁+)、AIGC 创意(6 岁+)、无人机(8 岁+)、科学实验营(4 岁+);专业与职业侧对应人工智能、具身智能、低空经济、储能新能源、数字金融、脑机认知等新设方向。
- 用途区分:才艺/课程用于报班;专业用于选科与志愿;职业用于职业启蒙与成人版职业罗盘。

### 4.6 行为对照库(20 项,反向口径)
`BEHAVIOR` 每项列出关联指标;`fit` = 关联指标均分,**升序**排列,分数越低越说明该行为是家长当前正面对的问题。
例:好动(b3/b2/b5/n2/g5)、分心(b3/b5/n1/n2/m1/v1/v2/v3/g1/i1/i3)、记忆力欠佳(l4/l1/g1/g2/g3/v1/v3/v2/n3/n4/m4)、缺乏耐心(i3)、不收拾玩具(g2/n1/n3/n4/b2/b4/i1/i3)。
口径要求:只做能力面解释,不给「过动倾向」等鉴定结论;用「以优势带动弱势」给建议。

## 6. 对话意图判定与分支
意图优先级(顺序不可交换):情绪 → 报告 → 事件 → 短追问 → 决策/比较 → 学科 → 培养规划 → 负反馈 → 求助 → 建档 → 兴趣自述 → 科普兜底。
另有元指令先于以上全部:重置(重来/清空)、帮助(能做什么)、快速自评作答中。

关键口径:
- `report` 必须含「报告/结果」字样;裸「分析一下」是提问。
- `event` 需「最近/今天/昨天」+ 行为;带「为什么/怎么办」则转为求助。
- `followup` 是 ≤12 字的短追问(还有呢/具体怎么做/举个例子),优先级高于一切新话题。
- `decision`(该不该/值不值得/有没有天赋/前景)在 `advise` 之前,但让位给明确学科名(subject)与归因语气(advise)。
- `compare` 需要两个候选项,或「哪个好/怎么选/报什么班/学什么好」;裸「还是」是副词,不算比较。
- `feedback` 负反馈(说了没用/不对/太笼统)优先于求助:先修正判断再谈建议。
- `emotion` 只在无「记一下」时生效;回复先共情、只问一个问题(最近天天 vs 这两周),不抛方案。
- `subject` 命中学科名/学科别名即进入学科潜能。
- `focus`(从哪开始培养/重点培养什么)在明确归因语气时让位 advise。
- `scores` 数字须紧跟智能/指标名且带「分」或 ≥20,避免「8 岁」被当成 8 分。
- `profile` 抽取年龄/性别/称呼/目的;「我儿子/女儿」可推断性别与视角。
- `traits` 自述(喜欢/擅长/担心/习惯/性格/家庭/学业 7 类)静默入画像并确认。
- `onboarding` 仅当 `touchedProfile` 为真且未命中 10 类豁免(advise/event/subject/decision/compare/focus/followup/feedback/traits/emotion)。
- 无报告时统一给三条路:8 题快速自评、直接报分数、先聊;8 题自评 `15 + (v−1)×17.5`,其余指标按同智能均值补齐,属近似值(R-07)。

比较选择 `chatCompareReply`:把选项映射到智能(乐器/声乐→音乐,绘画→视觉,编程棋类→逻辑,舞蹈/运动→肢体,口才→语言,自然→自然);两者分差 <8 分视为同档,建议各试一个月;裁决层给不出目标时退回剖面对比。

## 7. 陪伴层:归因、置信度、处方(agent_coach.js)

habit 域指标从 b4 改为 i1(I-038):习惯本质是自我调控,不是精细动作。

### 7.2 归因矩阵(能力基础 × 近 14 天事件)
`fit` = 该域关联指标均分;`recentN` = 近 14 天同域事件数;`avgInt` = 事件平均强度(1-5)。

| 条件 | kind | 说法 |
|---|---|---|
| 无报告(fit=null) | none | 只给补齐依据,绝不出处方 |
| fit≥60 且 recentN≥2 | env | 「能力不弱,更像节奏/环境/关系出了问题,先调环境」 |
| fit≤45 | trait | 「底子还薄,多催没用,切小任务、放低起点、搭支架」 |
| 45<fit<60 且 recentN≥2 | mix | 「能力够用,但环境在反复触发,先找触发点」 |
| fit≥60 且无近期事件 | env | 「能力面看不出短板,更可能是习惯/环境,缺事实不下定论」+ 请记 2-3 次具体情形 |
| 45<fit<60 且无近期事件 | mix | 给能力推断(指向域内相对最低项)并标「待事实校准」 |

I-042 教训:域内相对最低项不能一律说成「卡点」。≥60 分时说「卡在这儿」自相矛盾,必须改口为「能力不弱,更像习惯或环境」。

### 7.3 置信度
```
score = 0.45(有报告) + min(0.35, recentN × 0.12) + 0.2(域内 5 项标准差 ≤ 12)
recentN < 2 → score = min(score, 0.55)
档位:≥0.75 高;≥0.5 中;其余低。字段名用 reason(不用 note,前端依赖)
```
对话里不报数值,只说「六七成把握」及理由;低把握直说「这更多是推测」。

### 7.4 处方四型与节奏
每域 4 条候选,按归因取 3 条:

| 型 | 作用 | 选用条件 |
|---|---|---|
| lev | 杠杆:用本域最高项切入 | 恒选 |
| tgt | 降门槛:把本域最低项的要求砍小 | 恒选(但 tgt≥60 时中央改写,见下) |
| env | 环境:固定开工信号/节奏/规则/小圈子 | 归因为 env 或 mix |
| trait | 支架:拆步骤、流程卡、固定角色 | 归因为 trait |

- 证据挂载:lev 卡挂本域最高项证据;tgt 卡挂最低项;第三张挂最高+最低;有事件时再挂最近 1 条事件。
- 中央改写:tgt 分数 ≥60 时,九域统一改说「把这项排进每天的固定安排,底子不差,用起来才更顺」,不再说「砍门槛」。
- 节奏:每轮最多推进 2 条;同域追问先引用上次两条(「上次那两条先试了吗」),再从第 3 条继续;给完转反馈循环,问执行情况与卡点。
- 无报告:只返回一条「先补齐依据:生成报告 + 记录 2 条具体事件」的观察型动作。

### 7.5 事件窗口与上限
| 用途 | 窗口 |
|---|---|
| 归因 | 近 14 天 |
| 处方取事件证据 | 近 120 天,最多 5 条 |
| 学科潜能 | 近 180 天 |
| 行为画像 | 近 90 天 |

上限:事件 500、洞察 200、特性 80;特性按 `kind + text` 去重并累计次数。

### 7.6 学科潜能
`score = 0.5×相关能力项均分 + 0.3×兴趣事件密度(每条 20 分,封顶 100) + 0.2×当前表现(1-5 折算 0-100,无表现时用能力均分)`

| 情况 | 分档 |
|---|---|
| n=0 | 待验证(先按分数推) |
| n≥2 且 score≥65 | 强潜能 |
| score≥55 | 待验证 |
| 其余 | 暂不匹配 |

学科→指标映射:语文 l1/l3/l4/l5;数学 g1/g3/g4/v3;英语 l1/l2/l4/m1;物理 g1/g5/g4/v3;化学 g5/g2/n1;生物 n1/n3/n4;历史 l4/g2/i1;地理 v3/n1/n3;道法 l2/i4/s5;信息技术 g3/g5/v3;美术 v1/v2/v4/v5;音乐 m1/m2/m4/m5;体育 b2/b3/b5。

### 7.7 决策与裁决
- 四域置信度上限:智力开发 0.95、天赋特长 0.88、专业选择 0.66、职业规划 0.56(越远越保守)。
- 综合置信度 = min(加权值, 0.35 + 0.65 × 最弱项),木桶原理;可塑性只说投入产出比,不承诺效果。
- 边界:薪资预测、录取概率、临床诊断三类拦截;儿童边界不拦截(家长代问,标 delegate)。
- 裁决卡只属 decision;advise 只在「归因 + 该不该」混合问法时追加,且放在处方之后;同一份分数问两次结论一致。
- 年龄适配:<18 岁用学龄前/小学/中学/高中口径。

### 7.8 兴趣画像
7 类,每轮静默抽取,`kind + text` 去重:兴趣 interest、擅长 strength、担心 concern、习惯 habit、性格 personality、家庭 family、学业 school(如「数学考了 92 分」)。advise / focus 开场可引用最近一条兴趣(「他喜欢恐龙,这条我一直记着」)。

## 8. 表达规范与 LLM 风格守卫
五条口径(`LLM_STYLE_RULES` 是唯一真源,经 `llmStylePromptBlock()` 注入 system prompt):结论先行;事实与推断分开;术语红线;不贴标签;情绪先接住。

### 8.1 术语映射(硬替换,长模式在前)
| 内部术语 | 上屏说法 |
|---|---|
| 置信度:高/中/低 | 大概七八成 / 六七成 / 四五成把握 |
| 能力项 | 这项能力 |
| 本域 / 该域 / 域内 / 本维度 | 这块 |
| 归因(分析) | 原因 |
| 一致性 | 能不能对上 |
| 杠杆 | 抓手 |
| 卡点 | 卡住的地方 |
| 维度 | 方面 |
| 最弱的一环 / 最薄的一环 | 相对靠后的一项 |
| 短板 | 值得补的地方 |
| 垫底 | 靠后 |
| 缺陷 / 硬伤 | 待补的地方 |
| 【域标签】 | 直接删除,正文自然起句 |

枚举翻译:`mix`→两者都有、`trait`→更偏特点、`env`→更偏环境、`none`→还说不准。

### 8.2 只标记不改写(避免语序风险)
- `no-conclusion`:长度 >60 且开头无结论信号。
- `mixed-inference`:同段既有断言词(就是/一定/说明/证明)又有推断词(可能/也许/推测),却没有任何推断标注(推断/按分数/不确定/还缺)。

### 8.3 守卫链顺序
`llmChat` 拿到输出 → `mirEnforce`(安全闸门,命中越界整段改写成安全文案,传 maxChars=600)→ `llmStyleGuard`(术语→标签→人格定性→枚举→去 Markdown→按句裁剪→多问句收敛为 1 个)。
顺序不可反:反了会被闸门整段替换,风格清洗白做。
人格定性改写示例:「他就是懒」→「他这次更像是还没找到动力」;「多动症」→「需专业评估」;「你太焦虑」→「你已经很用力了」。
规则自生成的回复不过守卫链(会被误裁),所以 `agent_chat.js` 手写文案必须人工对齐这套口径。

## 9. 档案、存储与运行时
- 回放 `archiveReplay`:按快照原样复现;重算 `archiveRecompute`:用留档 `source.raw` 按当前口径生成新视图;二者都不改历史。
- 自动存档:串行队列 + 去重(当天 + 相同 40 项原始录入 + 相同 profile)。
- 存档 `archiveFromReport` 必带 `fusionVer`、`source.raw`、`source.quizAnswers`,否则无法重算。
- 成员隔离:`mi_archive_v1__<mid>` / `mi_coach_v1__<mid>`;桌面版落盘 `data/members/<mid>/{archives, coach.json}`。
- 成员/导入对话框必须自制 modal,禁用原生 `prompt`/`confirm`(Edge --app 下静默返回 null)。
- 分享链接 `?s=` 携带 40 项分数必须手拼逗号(`URLSearchParams` 会转义成 `%2C`);链接打开只展示不落库。
- 加密导出:PBKDF2-SHA256(15 万次)+ AES-GCM 256,口令 ≥6 位;仅覆盖导出包,本地落盘仍是明文(R-02)。
- TTS:`ttsChunks` 清洗 Markdown、标点转折停顿、按句切 ≤120 字、上限 8 块;一轮回复只聚合朗读一次(`chatSpeakText`),`kind:'card'` 跳过。
- 语音输入:抽音轨 → 16k 单声道 → 本地 Whisper-base 转写(首次约 50MB)→ 文本入输入框待用户核对;上限 120MB / 10 分钟。
- PDF 导入:内联 pdf.js(fake worker,file:// 可用)。指标分 = 智能分 × 比率 ÷ 该智能 5 项比率均值;双路写入 40 项指标 + 8 智能分 `intelManual`;报告内智能排序不写 `g_ranks`(先天排序 ≠ 主观排序)。非模板/扫描件明确说未识别,不猜测、不填部分值。
- 桌面运行时:仅绑 `127.0.0.1`,`/api/llm/*` 只转发本机回环 Ollama;热更新靠 `?v=<mtime-size>` 指纹 + 30 秒版本比对。

## 10. 质量保障
- 自动化测试 18 套 / 1116 断言,改动前后全绿;意图覆盖诊断必须 0 MISS。
- 改意图分支:先核对优先级全表 + 三处 onboarding 豁免 + `chatIntent`/`chatTurn` 分支顺序一致。

## 12. 与本项目 mhagent 的关系
