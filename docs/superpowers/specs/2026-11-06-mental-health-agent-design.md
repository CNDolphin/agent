# 心理健康 Agent 设计文档

日期:2026-11-06
状态:待用户评审(本文档只做设计,不进入开发)

## 1. 目标与范围

做一个独立运行的 Python Agent,具备三组技能,模型调用经自建后端网关接入公司 token 平台并计费。

**三组技能**
1. 心理健康支持:知识推送、情绪日记、正念/呼吸练习、CBT 自助工具的结构化呈现。
2. 评估与风险筛查:情绪状态评估、压力指数反馈、风险筛查。
3. 基因报告解读:基于用户提供的现成评估报告,给出兴趣、特长及学习就业的方向性参考。MVP 只预留接口与框架。

**已确认的前提**
- 目标用户:通用大众。
- Agent 形态:独立 Python 程序。
- 后端:Go (go-zero),职责是用户管理、积分计费、模型网关、紧急通知。
- MVP:技能 1 + 2 + 后端;技能 3 只预留。
- 积分来源:注册赠送 100 积分;购买套餐时随套餐赠送积分;运营可手动发放。**积分不与人民币挂钩**,套餐的售价与赠送积分数是各自独立的配置。
- 支付:MVP 提供 `mock` 与 `manual`(线下收款、后台确认)两种渠道;真实支付渠道待定,通过 `PaymentProvider` 接口接入。
- 管理后台:需要页面,React + Ant Design,属于 MVP。
- 上游模型接口参考 DeepSeek(OpenAI 兼容 `/chat/completions`),模型 `deepseek-flash`、`deepseek-v4-pro`;上游通过 `Upstream` 接口隔离,可替换。
- 注册/登录:手机号 + 短信验证码,首次登录自动注册,无密码。
- 短信与邮件通道:阿里云。只接入 SDK 并留配置文件,本阶段不为其写测试,开发与测试用 mock。
- 模型计价:每个模型的价格在管理端调整,留历史,即时生效;未定价的模型默认不可用。

**不做**
- H5 前端、管理后台(P2)、云端同步、多租户、原始基因数据处理。

## 2. 隐私与数据归属

| 数据 | 位置 | 说明 |
|---|---|---|
| 日记、量表结果、压力指数历史 | 仅本地 | 加密存储 |
| 基因评估报告 | 仅本地 | 不上传,后端无报告相关功能 |
| 紧急联系人 | 仅本地 | 仅在高风险且用户已授权时,随通知请求发给后端,后端发送后丢弃,不落库 |
| 聊天内容 | 仅本地 | 经网关发往模型,网关不存正文,只记 token 数、模型名、耗时 |
| 账号、积分账本、用量流水、通知发送结果 | 后端 | 计费与审计必需 |

约束:
- 本地数据加密(SQLCipher 或等价方案),密钥由用户口令派生,不上传。
- 换设备需用户主动加密导出/导入,后端不同步。
- 后端日志和审计表禁止出现消息正文、日记内容、联系人信息。
- 高风险时若用户未预先授权紧急联系人通知,Agent 只引导用户自行联系,不触发后端通知。

## 3. 总体架构

```
用户 ──► Python Agent(本地)──► Go 后端(网关)──► token 平台
          │                        ├─ 鉴权
          │                        ├─ 积分:冻结 → 调用 → 结算
          │                        ├─ 用量流水
          │                        └─ 紧急通知发送
          └─ 本地加密存储(日记/量表/报告/联系人/会话)
```

Agent 不持有 token 平台密钥,只持有用户登录令牌。

## 4. 技能设计

### 4.1 mental-health
- 知识推送:内置分类知识库(睡眠、焦虑、压力、情绪调节),按话题或近期状态选取并改写。只做科普,不诊断,不推荐药物。
- 情绪日记:引导记录事件、情绪、强度 0-10、想法;支持周回顾。只存用户明确要记的内容。
- 正念/呼吸:固定脚本(4-7-8、箱式呼吸、身体扫描、5-4-3-2-1 接地),模型负责带节奏引导,用户不适即停。
- CBT 工具:想法记录表、认知扭曲识别、行为激活计划、问题解决五步法。定位为自助工具,不是治疗。

### 4.2 assessment
- 量表:PHQ-9、GAD-7、PSS-10。题目、选项、计分、分级全部在代码,模型不算分。
- 压力指数:0-100。由 PSS-10 标准化得分与近 14 天日记情绪强度趋势按固定权重合成,公式写在代码并有单元测试。
- 反馈:模型据分级结果解释并给下一步建议;只写"筛查提示",不写"诊断"。
- 风险筛查:PHQ-9 第 9 题非 0,或对话出现自伤/自杀表达,触发风险流程。

### 4.3 gene-guidance(预留)
- MVP 只放 SKILL.md 框架与固定声明。
- 原则:倾向性参考而非定论;不对能力上限或"天赋不足"断言;报告只在本地使用。
- 报告到位后补充:报告格式说明、维度到方向的映射资料、本地导入工具。

## 5. 安全层

每轮用户消息先经 `safety.py`,模型输出再过一次出站检查。

| 级别 | 触发 | 处置 |
|---|---|---|
| 低 | 无风险信号 | 正常继续 |
| 中 | 持续低落、绝望感、PHQ-9 偏高 | 温和回应,主动提供评估/练习,建议联系专业人士 |
| 高 | 明确自伤/自杀意图或计划,或 PHQ-9 第 9 题非 0 且对话佐证 | 中止常规流程,固定危机话术与热线(如 12356、120);已授权则通知紧急联系人,未授权则引导用户自行联系;之后模型只做陪伴,不做评估/练习 |

判定:规则/关键词先判,再用模型分类复核,取较高级别。规则命中高风险时不等待模型,立即输出危机话术。

关键例外:危机流程不受积分余额限制。余额为零时,危机话术由 Agent 本地直接输出,不经网关;陪伴性对话在余额为零时可降级为本地固定回应并提示购买套餐。

## 6. 后端设计

### 6.1 积分规则
- 公式:`积分 = ceil((缓存命中输入 × 命中单价 + 缓存未命中输入 × 未命中单价 + 输出 × 输出单价) / 1,000,000)`,单价单位为积分/百万 token,全部整数运算。DeepSeek 的输入分缓存命中与未命中两档价格,用量字段为 `prompt_cache_hit_tokens`、`prompt_cache_miss_tokens`。单价按模型配置,管理端修改后立即生效;一次请求内的冻结与结算使用开始时取到的同一份价格。
- 流程:请求前按预估上限冻结,结束后按实际用量结算并释放差额。流式中断按已产生用量结算。
- 账本:只增不改的流水(赠送 grant、套餐入账 recharge、冻结、释放、消耗、退款),余额由流水汇总得出;每笔带 `request_id` 保证幂等(`UNIQUE(user_id, request_id, type)`)。冻结在单个 PostgreSQL 事务内对账户行加 `FOR UPDATE` 锁完成余额校验与落账;Redis 只用于限流,不参与积分一致性。

### 6.2 后端功能清单

**P0**
1. 用户管理:手机号验证码登录(首次自动注册)、令牌刷新、注销账号;手机号只存哈希与脱敏串
2. 积分账户:余额、流水账本、冻结/结算/退款、幂等
3. 模型网关:转发 token 平台、用量提取、计费、限流、超时重试、流式透传,不存消息正文
4. 计价配置与管理端 API:按模型的输入(命中/未命中)/输出单价,修改必填原因并留历史;积分发放、用户与用量查询;独立的管理员账号与角色
5. 紧急通知:通过阿里云短信/邮件发送,模板白名单与频率限制,记录发送结果,不存联系人信息与对话内容
6. 同意书:版本与签署记录,明确说明本地数据与经网关数据的范围
7. 审计日志:积分变动、通知触发,只记事件类型与时间

**P0(续)**
8. 套餐与订单:管理端配置套餐(名称、售价、赠送积分、上下架),用户下单购买,支付成功后一次性入账;订单保存套餐快照;MVP 渠道为 mock 与 manual
9. 管理后台页面:模型价格(必填修改原因、留历史)、套餐、订单(确认收款/取消)、用户查询、积分发放、用量汇总、通知记录

**P1**
8. 真实支付渠道对接(微信/支付宝等,渠道待定);签到、任务、兑换码、邀请奖励不做
9. 余额不足提醒;积分过期后置
10. 风险事件元数据:仅等级、动作、通知结果,不记原话
11. 内容库管理:知识文章增删改、分类、上下线;Agent 启动时拉取到本地
12. 量表题库与计分规则版本化:Agent 拉取,本地结果保存版本号
13. 通知通道抽象:短信/站内信/邮件
14. 监控告警:网关错误率、token 平台延迟、积分对账差异

**P2**
15. 管理后台的高级能力:多级审批、操作回滚(基础页面已在 P0)
16. 用量与成本报表、与 token 平台账单对账
17. 反滥用:注册限制、设备/IP 风控、异常消耗检测
18. 会员/套餐

后端无:报告管理、日记/量表云存储、会话内容存储。数据导出/删除仅针对账号与账本。

### 6.3 接口概要
- `POST /auth/sms/send` `POST /auth/login` `POST /auth/refresh` `DELETE /account`
- `/admin/*`:管理员登录、模型定价、积分发放、用户与用量查询(见后端计划 Task 14)
- `GET /credits/balance` `GET /credits/ledger`
- `POST /llm/chat`(支持 SSE 流式;请求头带 `request_id`)
- `POST /notify/emergency`(体内含联系方式与模板 ID,发送后不落库)
- `POST /consent` `GET /consent/latest`
- `GET /content/articles` `GET /scales/versions`(P1)

## 7. 错误处理
- 网关不可用或超时:Agent 提示稍后重试;风险检查与危机话术不依赖网关,仍然可用。
- 积分不足:拒绝新的模型调用并提示购买套餐;危机流程除外。
- 本地库损坏或口令错误:不覆盖原文件,提示恢复或导入备份。
- 通知发送失败:提示用户自行联系,并给出可复制的求助文字。

## 8. 测试策略
- 量表计分、分级、压力指数、积分公式:纯函数单元测试,含边界值。
- 安全层:构造高/中/低风险语料集做回归测试,高风险漏判视为严重缺陷。
- 网关与账本:冻结/结算/退款/幂等/并发/流式中断的集成测试。
- Agent 循环:用 mock LLM 做端到端对话测试。
- 隐私:检查后端日志与数据库中不出现正文、联系人和日记内容。

## 9. 风险与待定项
- 用户对话内容会经网关发送给第三方模型服务(DeepSeek),必须在同意书与隐私政策中明示,并由法务确认对方的数据处理条款。
- 阿里云短信签名与模板需要审核(验证码、紧急联系人通知各一个),耗时较长,应在开发早期提交;邮件推送需验证发信域名。阿里云的真实调用本阶段不做测试,上线前需在预发环境人工验证一次。
- 积分不挂钩人民币,运营需自行核算"套餐赠送积分 × 模型单价"与上游实际成本,避免亏损。
- 暂缓项(本阶段不处理,上线前必须回头):PSS-10 授权、危机话术与风险语料的专业审阅、未成年人策略。
- 若上游账户欠费(DeepSeek 返回 402)或密钥失效(401),用户侧统一表现为 502,同时产生告警,需要监控。
- 未成年人:定位通用大众,注册时需声明年龄并在同意书中说明;是否限制未成年人使用需后续确认。
- 合规:心理类应用的上架与内容合规要求需另行确认。
- 危机话术与热线信息需由具备资质的人审阅。
- 量表版权:PHQ-9、GAD-7 可免费使用;PSS-10 的题目文本在商用前需确认授权。计划中题库与计分逻辑分离(题库为 JSON 数据文件),PSS-10 题目文本待授权确认后再填入。
- 本地加密口令丢失即数据无法找回,需在产品上明确提示。
